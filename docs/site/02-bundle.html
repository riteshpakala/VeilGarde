What does the detector ship?

On the bytes the detector reads, how each is held to its hash, and the JSON it writes.

The detector ships as a bundle: a folder of model files and one manifest that names them. It lives in Sources/VeilGardeInference/Resources and travels inside the package, so a build of VeilGarde carries the exact models Garde ran.

Today the bundle holds 14 artifacts beside its manifest. Seven are shared models and contracts: the warp tile model and its sensor copy, the sensor calibration, the fusion head and its frozen reference, the stack combiner and the cross-domain centroids. The other seven are specialist heads. The neural weights are not in it: the manifest records the 4 files it expects beside it and their hashes. The noiseprint's, 130 KB, ships in the same folder; DINOv2's are imported from Hugging Face's checkpoint.

Every file held to its hash

Each artifact in the manifest carries its role, its file name, its SHA-256, its size and where its bytes came from. Loading a bundle re-hashes every file the manifest names and refuses a mismatch, as an error and never as a warning. A file the manifest does not name is ignored.

The shipped bundle is verified once per process, the first time anything reads it. Everything that reads a shipped artifact asks the bundle for it by role.

Twelve files are Garde's byte for byte, under shorter names. A file's name is free, but its bytes are not: the result JSON reports the warp models' hashes, and the calibration contract is bound to the sensor model's bytes.

Two are VeilGarde's own, from the pruning study, and the manifest's history records each change. The calibration is two cuts on the tile vote where Garde's Platt contract changed its call. The combiner is Garde's weights without the art-pair adjudicator, whose head left the bundle with it.

What may never move

Some roles are frozen: the warp tile model and its sensor copy, the fusion reference, noiseprint and the backbones. The flywheel may promote a new head, a new combiner or a new fusion head, but never over a frozen role.

The reason is what was fitted against those bytes. The calibration contract is bound to the sensor model's hash, and the research's model registry records that re-freezing the fusion reference means re-validating every arbiter threshold.

The bundle names one file per role. The human head ships as v4 alone, where Garde bundled v1 to v4 with ordered fallback names and loaded only v4.

The result, schema v2

Every detection ends as one JSON object. It is the one contract the command line, the battery and every downstream surface read, so it is the one place VeilGarde keeps Garde's bytes rather than Garde's names.

The encoder was moved, not rewritten: the same keys, the same conversions to Double, and JSONSerialization with sorted keys. On 2026-10-19 the warp result JSON equalled Garde's for both parity crops, times_sec aside, and 20 of 20 sampled images were the same.

Since the two cuts, the sensor fields differ on purpose: sensor_p is the tile vote itself, and sensor_calibration holds the cuts. The call is Garde's, and every other field is still Garde's for the same image.
