How does the detector reach one verdict?

On the one entry point of the full detector, the order in which its evidence compounds, and the result it writes.

The router is where the layers meet. It picks the image's domain, runs that domain's base expert, then lets a short list of high-precision steps revise the verdict, always in the same order. Every step is one file.

The number that comes out keeps the base's meaning: the probability that the image was generated, called at 0.5.

Two domains

A photograph and a screenshot need different experts. The router reads the image's signals once, then picks the screenshot domain when the flat-UI gate fires and the camera domain otherwise. A caller's hint overrides the gate.

Routing is never by image size. A small image is still a camera image, and the preview tail of chapter 2 handles what size does to the base.

The camera domain's expert is the fusion head of chapter 1. The screenshot domain's expert is a content head trained on screenshots alone.

Seven stages, one after another

Detection is a chain of stages, each handing its output to the next. The change explorer walks each one as a trail of its own.

#StageWhat it doesTrail

The warp residual crosses into detection only as numbers. Its code lives in the watermark, and the shipped fusion head does not read it.

The order of the steps

The order is fixed because each step reads what the one before it wrote.

#StepWhat it does
1CapturePriorsA valid, present capture signature suppresses every generated-side head. Otherwise the combiner of chapter 2 pools the base with the art, blur and human priors.
2FrameSeamWhen a real verdict hides a uniform dark frame, it runs the stack again on the interior and takes decisive interior evidence.
3SemanticChainThe semantic-tile map and its majority, then the projection that lets only the production profile commit a probe's revision.
3aPreviewTailA small image read as generated with a clean semantic vote flips to real only when the preview head and the neutralized fusion head both read it real.

Zoom escalation, the x-domain gate and the render taxonomy were removed when the detector became two lanes; none of them ran by default.

The verdict is frozen before the semantic chain as the pre-semantic state, and kept in the diagnostics. That is what makes a route replayable: the chain's revisions can be read against what came before them.

Stacking, not blending

Each step either keeps the verdict or revises it on decisive evidence, and each gate was measured before it went live. The frame seam takes the interior's verdict only when it reads at least 0.70 and sits at least 0.20 above the outer score. The preview tail flips only under three agreeing reads.

The cost of a gate is a step that rarely fires. The alternative, one model that blends every signal, raised real false positives from 8% to as much as 92% in the research's measurement.

What the result holds

The result is one JSON object with one verdict. It names the base expert that ran, the verdict and its operating point, and the image's size. Around them sits the evidence: the capture signature, the stack's rows, the semantic map and a trace of which steps ran.

The result is schema v3, VeilGarde's own. Schema v2 was the reference's bytes and carried a second verdict, the camera-sensor score and its calibration; none of them exists once the warp leaves detection.

The keys are written sorted, so the same result is always the same bytes. A golden file can hold it, and the battery reads its verdict from it.

The goldens

Two crops hold the whole path. Their routed results are VeilGarde's own, written by veilgarde route --json, and the golden tests compare every later run with them: every label exact, every number within 1e-4.

The tolerance is MLX's. DINOv2's matrix kernels move with Frigate's MLX revision by about 1e-5, so the numbers are held close and the labels exact.

Until the two lanes the goldens were Garde's own runs, and VeilGarde's route equalled Garde's byte for byte on 37 images with Garde's Metal library. That comparison retired with schema v2; chapter 10 keeps its record.

For engineers: where each piece lives
  • DetectionSignals reads each signal at most once and caches it; RouteState carries the verdict, the stack's rows and the semantic state between steps.
  • PublicSurface.routed joins the base's operating point with the router's verdict, and ResultJSON writes it; RouteBatch runs a JSONL manifest through the same path.
  • The route golden tests hold this path to its own goldens; rewrite the goldens with veilgarde route --json only when a change is meant to move them, and say so in the ledger.
